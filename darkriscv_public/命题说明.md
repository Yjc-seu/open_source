# 赛题：RV32I 处理器核 — 激励生成任务（最高难档）

## 1. 赛题背景

给定一个 **RV32I 处理器核**（`darkriscv_public`，基于开源 darklife/darkriscv，
BSD-3-Clause，三级流水），支持 RV32I 完整整数指令集（含 CSR 系统指令与
EBREAK 异常机制）、内置指令/数据 RAM（程序与数据初值经 cfg 动作逐字节
装载）、确定时序的内存控制器（指令总线寄存器读 IPC=1；数据总线 1 拍等待
状态，load/store 2 拍）。你的任务是**设计并生成测试激励（stimulus）**，使
被测设计（DUT）的**功能覆盖率**最大化。

DUT 在标准 RV32I 之上带有若干需要**主动探测**的深水区特性：隐藏的"正确
结束指令 opcode 子集"（只有以这些 opcode 的指令触发陷阱结束程序才会进入
hold 并上报 `done_ok`，完全黑盒）、隐藏的驻留窗口长度（TRAP_HOLD_N，期间
屏蔽 run/cfg 并复位挂起 CPU）、以及 stvec 陷阱序言协议、分支方向、
load→ALU→store 数据流、trap 后重启等时序特性。功能的完整定义见
`dut/dut_spec.md`（规格书）与 `dut/coverage_meta.json` / `dut/covergroup.svh`
（覆盖定义）。

## 2. 评测方式

- 评分依据：在**评测 DUT**（与本地 Verilator 模型一致）上运行你生成的激励
  序列后，`coverage_simulator.py` 统计的 **bin 命中数 / 总 bin 数（128 个）**。
- 激励以**动作序列**形式提交：每个时钟周期一个动作，
  `action = [cfg_wr, cfg_sel, cfg_data, run, pad0..pad10]`（见规格书 §4）。
  典型流程：cfg_sel=0/1 设装载地址 → cfg_sel=2 逐字节写指令/数据 → run=1
  释放执行 → 等待 trap（cov_trap 脉冲）→ run=0 复位装载下一程序。
  **每个程序必须自带 stvec 序言**（LUI x5,1; ADDI x5,x5,0x800;
  CSRRW x0,0x105,x5），EBREAK/非法指令/非对齐访问才会触发陷阱事件。
- 本地开发阶段可通过 `local_sim.py` + `coverage_simulator.py` 快速迭代；
  评测阶段以真实 DUT 仿真结果为准。
- 128 个 bin 中 112 个在公开占位参数下可达；16 个依赖隐藏参数（评测端注入
  真值后可达）。要求尽可能多的 bin 被命中。

## 4. 使用流程

```bash
# 1) 本地快速迭代（Python，无需 Verilator）
#    推荐直接用 harness（与评测一致的动作解码 + 覆盖率）：
python3 - <<'EOF'
import sys; sys.path.insert(0, "darkriscv_public")
import numpy as np
from harness import DarkriscvHarness

h = DarkriscvHarness(backend="local")   # 评测端注入真值时传 secrets
h.reset()
# 动作：15 维 [cfg_wr, cfg_sel, cfg_data, run, pad0..pad10]
def cfg(sel, data):
    a = [0.0]*15; a[0]=1.0; a[1]=sel; a[2]=data
    return np.asarray(a, dtype=np.float32)
def run(v):
    a = [0.0]*15; a[3]=v
    return np.asarray(a, dtype=np.float32)

# stvec 序言 + EBREAK：LUI x5,1; ADDI x5,x5,0x800; CSRRW x0,stvec,x5; EBREAK
prog = [0x000012B7, 0x80028293, 0x10529073, 0x00100073]
for a in [cfg(0,0), cfg(1,0)] + [cfg(2,(w>>(8*b))&0xFF) for w in prog for b in range(4)]:
    h.step(a)
for a in [run(1)]*40:
    h.step(a)
print("coverage:", h.coverage)
EOF

# 2) Verilator 仿真（真实 DUT，Linux/WSL）
cd darkriscv_public/verilator_harness && ./build.sh   # 构建（公开占位参数）
python3 run_verilator.py                             # 驱动 DUT

# 3) 对拍校验（本地模型与 Verilator 周期一致性，注入隐藏真值后运行）
cd darkriscv_public && python3 cross_check.py
```

## 5. 提示

- 覆盖率报告只返回 **bin 命中向量**（哪些 bin 命中），不暴露内部信号。
- 存在若干**隐藏参数**（正确结束 opcode 子集、驻留窗口长度），值不随包
  公布，需通过行为反馈探测。
- **陷阱协议**：程序必须写 stvec=0x800（CSRRW 序言）才会产生陷阱事件；
  上游 darkriscv 的 OP/OP-IMM 解码覆盖全部 funct3/funct7（无"非法 OP-IMM
  形式"），非法指令 = 未解码 opcode（如 FENCE 0x0F、custom 0x2F/0x5B/0x6B/
  0x7B 等）；ECALL 是 NOP（上游行为）。结束指令应放在 ≤0x7F0（取指指针
  超前 PC 8 字节，0x7F4 处陷阱向量取指与取指超前重合被过滤）。
- 上游陷阱后核心跳陷阱向量；匹配隐藏子集才进入 hold 并自动重启（pc=0，
  寄存器保持），非匹配陷阱冻结（run 复位重启）。
- 数据总线地址为字节地址（DBE 指明字节通道）；load/store 各 2 拍。
- 建议覆盖：stvec 序言 + 各 opcode/funct3/寄存器边界 × load/store × 分支
  双向 × 调用-返回（前跳 ≥16 字节）× 循环迭代 × 数据流序列 ×（注入真值
  后）hold 窗口与 done_ok 类别。
