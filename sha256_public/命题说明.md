# 赛题：SHA-256 哈希引擎 — 激励生成任务（中高难档）

## 1. 赛题背景

给定一个 **SHA-256 哈希计算引擎**（`sha256_public`，基于开源
secworks/sha256 的迭代压缩核心，BSD-2-Clause 许可），支持 512 位块按字节
装载、init/next 多块链式处理、摘要字节读出与 SHA-224/256 模式选择。你的
任务是**设计并生成测试激励（stimulus）**，使被测设计（DUT）的**功能覆盖
率**最大化。

DUT 在标准哈希引擎之上带有若干需要**主动探测**的深水区特性：隐藏的
"正确累计长度子集"（只有用这些长度完成摘要才会上报 `done_ok`，完全黑
盒）、正确长度完成后的隐藏驻留窗口（长度隐藏）、以及预装载续链（双块连
续）、长度边界、摘要字节边界等时序特性。功能的完整定义见
`dut/dut_spec.md`（规格书）与 `dut/coverage_meta.json` /
`dut/covergroup.svh`（覆盖定义）。

## 2. 评测方式

- 评分依据：在**评测 DUT**（与本地 Verilator 模型一致）上运行你生成的激励
  序列后，`coverage_simulator.py` 统计的 **bin 命中数 / 总 bin 数（95 个）**。
- 激励以**动作序列**形式提交：每个时钟周期一个动作，
  `action = [d0, d1, cfg_wr, cfg_sel, cfg_d0, cfg_d1, init_pulse,
  next_pulse, pad0..pad6]`（见规格书 §4）。
- 本地开发阶段可通过 `local_sim.py` + `coverage_simulator.py` 快速迭代；
  评测阶段以真实 DUT 仿真结果为准。
- 95 个 bin 中 73 个在公开占位参数下可达；22 个依赖隐藏参数（评测端注入真值
  后可达）。要求尽可能多的 bin 被命中。

## 4. 使用流程

```bash
# 1) 本地快速迭代（Python，无需 Verilator）
#    推荐直接用 harness（与评测一致的动作解码 + 覆盖率）：
python3 - <<'EOF'
import sys; sys.path.insert(0, "sha256_public")
import numpy as np
from harness import Sha256Harness

h = Sha256Harness(backend="local")     # 评测端注入真值时传 secrets
h.reset()
# 动作：15 维 [d0, d1, cfg_wr, cfg_sel, cfg_d0, cfg_d1,
#             init_pulse, next_pulse, pad0..pad6]
def wr_byte(b):
    a = [0.0]*15; a[0]=b; a[2]=1.0; a[3]=0.0
    return np.asarray(a, dtype=np.float32)
def pulse_init():
    a = [0.0]*15; a[6]=1.0
    return np.asarray(a, dtype=np.float32)
def wait(n):
    return np.zeros(15, dtype=np.float32)

for a in [wr_byte(i) for i in range(64)] + [pulse_init()] + [wait(0)]*100:
    h.step(a)
print("coverage:", h.coverage)
EOF

# 2) Verilator 仿真（真实 DUT，Linux/WSL）
cd sha256_public/verilator_harness && ./build.sh   # 构建（公开占位参数）
python3 run_verilator.py                           # 驱动 DUT

# 3) 对拍校验（本地模型与 Verilator 周期一致性，注入隐藏真值后运行）
cd sha256_public && python3 cross_check.py
```

## 5. 提示

- 覆盖率报告只返回 **bin 命中向量**（哪些 bin 命中），不暴露内部信号。
- 存在若干**隐藏参数**（正确累计长度子集、驻留窗口长度），值不随包公布，
  需通过观测总线或行为反馈探测。
- 覆盖点除基本/边界/条件/交叉外，还包含**时序窗口**、**跨周期（deep）**、
  以及**时序断言（SVA cover property，含 dataflow / timing_param）** 等类别；
  后者要求构造完整的时序序列而非单拍凑值。
- 上游核心每块固定 64+2 拍；**压缩期间 cfg 仍可接受**——可利用其预装载
  下一块，在 digest_valid 后 ≤2 拍内发 next，命中"双块连续"时序。
- 建议覆盖：块/摘要字节边界 × 长度边界（0/1/254/255） × init/next 链 ×
  完整装载（64 字节） × 空闲驻留与快速完成时序 ×（注入真值后）hold 窗口
  与 done_ok 类别。
